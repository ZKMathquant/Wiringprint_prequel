Generated by the bootstrap notebook; the tooling lives in `tools/` and `.github/workflows/`.

## How a run works

1. **Actions -> "Run notebooks on Kaggle" -> Run workflow.** Pick `all` or a comma list of notebook ids.
2. The job pushes a *thin runner kernel* to Kaggle (GPU on, internet on, private), waits until Kaggle reports
   it is queued/running, then **exits** (~1-3 min of Actions time, nothing is billed while Kaggle works).
3. On Kaggle the runner clones this repo **at the exact commit you launched from**, executes the notebook with
   papermill, and commits the result straight to GitHub using the `GH_TOKEN` Kaggle secret.
4. With several notebooks, each finishing runner starts the next one (one GPU session at a time by default).

```
runs/<run_id>/<notebook>/      successful runs - FROZEN, never overwritten
    <notebook>.executed.ipynb  the executed notebook (with all outputs)
    outputs/                   every file the notebook created (figures, csv, json, caches)
    run_manifest.json          status, timings, commit sha, GPU, first error, skipped files
    run.log  pip_freeze.txt  gpu.txt
failed/<run_id>/<notebook>/    failed / timed-out / preflight-failed attempts (same layout, partial results)
notebooks/                     the notebooks that get run (outputs stripped)
archive/uploaded_originals/    your originals as uploaded, with their old outputs
```

`run_id` looks like `20261001-143015-label`. Later runs get a new id and therefore a new folder; nothing from an
earlier run is touched. `.github/workflows/freeze-guard.yml` turns a push red if it changes anything that already
exists under `runs/` (put `[unfreeze]` in a commit message to allow a deliberate cleanup).

## Workflows

| Workflow | Use |
|---|---|
| **Run notebooks on Kaggle** | start one / several / all notebooks. Inputs: `notebooks`, `label`, `on_failure` (continue/stop), `lanes` (1 or 2 parallel GPU sessions), `resume_from`, `selfcheck` |
| **Kaggle status** | state of the kernel slots + latest runs (reads Kaggle once, ~20 s) |
| **Recover results from Kaggle** | if a run finished but its push failed: pulls the bundle from the kernel output into the repo |
| **Freeze guard** | automatic, flags edits to `runs/` |

* `selfcheck=true` runs a 1-2 minute **CPU** check on Kaggle: are the secrets attached, is the GitHub token able to push,
  is the HF token valid and licence-accepted for every model the notebooks load, is the internet on. **Do this first.**
* `resume_from=failed/<run_id>/<notebook>` seeds the working directory with the files an earlier attempt produced
  (useful for notebooks with a result cache such as `cmir_cache_*`), then runs again under the same `run_id`.
* Re-running a failed notebook with the *same* `run_id` completes that run; a successful result still lands in
  `runs/<run_id>/<notebook>/`.

## Secrets

| Where | Name | What |
|---|---|---|
| GitHub repo secrets (set by the bootstrap) | `KAGGLE_KEY` (+`KAGGLE_API_TOKEN` if you use a KGAT token) | lets the launcher push kernels. Username is in `config/project.json` |
| **Kaggle kernel secrets** (one-time, manual) | `GH_TOKEN` | fine-grained PAT limited to this repo: Contents RW, Actions RW |
| | `HF_TOKEN` | Hugging Face token (needed for gated models like Llama / Gemma) |

Kaggle has no API to attach secrets, so on each runner kernel (`iamakagggler/nid-wiringprint-prequel-a` and `iamakagggler/nid-wiringprint-prequel-b`) open
*Add-ons -> Secrets*, add the two secrets once and switch them **on** for that notebook. Use `selfcheck` to confirm.

**Secret mode = inline**: `GH_TOKEN`/`HF_TOKEN` are repo secrets (`RUNTIME_GH_TOKEN`, `RUNTIME_HF_TOKEN`) written into the PRIVATE kernel source at launch, so no Kaggle-side attaching is needed. Never make a runner kernel public.

## Limits to know

* Kaggle: ~30 GPU hours / week, 12 h per session, 2 concurrent GPU sessions. The runner stops the notebook
  ~40 min before the 12 h cap and pushes whatever exists to `failed/` so a long run never vanishes.
* Kaggle needs a phone-verified account for GPU and internet.
* Files over 95 MB are skipped (GitHub limit) and listed in `run_manifest.json`; a run's bundle is capped at 400 MB.
* If Kaggle kills the session abruptly (out-of-memory, platform restart) nothing can be pushed; the partial output
  stays in the kernel's output - use **Recover results from Kaggle** (only the latest version of a kernel keeps it).
* Kaggle slots: each runner kernel runs one notebook at a time; launching while a slot is busy waits up to 10 min, then fails.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| launch fails: `Kaggle refused the push` | GPU quota used up, account not phone-verified, or wrong `KAGGLE_KEY` |
| Kaggle log: `GH_TOKEN is not available` | secrets not attached to that runner kernel (see Secrets) |
| `failed/.../preflight_failed` mentions `gated` | accept the model licence on huggingface.co with the account that owns `HF_TOKEN` |
| `preflight_failed: gpu` | Kaggle gave a different GPU than `require_gpu_substring` in `config/project.json` |
| `chain: CHAIN_ERROR` | `GH_TOKEN` lacks Actions: write - start the remaining notebooks manually (see `runs/<run_id>/_chain_errors/`) |

## Shared code (`src/wiringprint`)

The helper functions the notebooks used to define (and copy between each other) live once in `src/wiringprint/`; each
notebook imports what it uses. Kaggle runs put the *pinned* commit's `src/` on `PYTHONPATH` and take the notebook from the
same commit, and `run_manifest.json` records `src_sha256`. Older helper versions that earlier notebooks depend on are kept in
`wiringprint/variants/`. Details, module map and the exact (mechanical) changes: [`docs/REFACTOR.md`](docs/REFACTOR.md).
`python tools/check_repo.py` (also run by the *Check repo* workflow on every push) verifies that every import resolves.
